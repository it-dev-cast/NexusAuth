Nexus One · Foundation Core

One identity for every module on the platform.

The Authentication Service issues every login and every permission for Nexus One — JWT-based, role-aware, and fully audited from day one. No module ships its own login screen or user table.

  • HS256-signed access & refresh tokens, with rotation on every refresh
  • Role-based access enforced identically at every API endpoint
  • Every action — success or denial — written to an immutable audit trail

* Required

Audit log

Audit trail

This resource is read-only by design — the only writer is the app itself (see app/services/audit_service.py). PII fields (email, bank account, PAN, Aadhaar, etc.) are masked in old/new value snapshots even for admins.

Events

Event stream

Every event mirrors an audit row 1:1 — it fires automatically whenever an action is audit-logged (see app/services/audit_service.py). Read-only by design; the only writer is the app itself. Nothing consumes this stream yet (no workflow engine is wired up) — this is the durable record ready for one later.

Your sessions

Each login creates an auth_sessions row. Refresh rotates it. Logout revokes it and records the access-token jti.
